# pius: impermanence readiness

Status: **prepared 2026-11-23; the root rollback is still disabled.** pius already imports
the impermanence module and the ZFS boot-rollback module, and the persistence binds are
live, but `cjv.impermanence.zfsBootRollback.rootDataset` is unset, so nothing is wiped
today. This note records what a rollback would lose, what has been moved/declared so far,
and the exact steps to enable it safely.

Related: `pius-disk-recovery.md` (the zsafe space recovery), `turing-unlock-assessment.md`
(the tiberius archive), `hosts/pius.nix` (`environment.persistence`,
`virtualisation.docker.daemon.settings`).

## What enabling the rollback would do

The module (`profiles/nixos/impermanence/rollback-zfs-boot.nix`) runs
`zfs rollback -r <rootDataset>@blank` in initrd, before `/sysroot` mounts. With
`rootDataset = "zlocal/root"`, every boot returns `/` to the state of that snapshot: only
what lives on `/persist` (or another dataset such as `/nix`, `/boot`, the pools) survives.
The persistence binds are active already, so the declared paths are on `/persist` and are
unaffected.

### Deliberately ephemeral (lost on a root rollback)

| path | size | why it is acceptable |
|---|---|---|
| `/var/lib/rabbitmq` | 568 KiB | firecrawl's job queue (Mnesia). Queues are transient; persisting them through a *bind* would replay stale jobs at the next boot, which is worse than starting empty. |
| `/var/lib/redis-firecrawl`, `/var/lib/redis-nextcloud` | ~80 KiB | caches by design. |
| `/var/lib/private/{blocky,pdf-translator,searx-health}` | < 5 KiB | empty/marker state; configs are Nix-generated. |
| `/var/lib/{fwupd,systemd,dhcpcd,udisks2,lastlog}`, `/var/log` (non-journal) | ~2 MiB | regenerated at boot or not needed. |
| `/home/samba` | empty | no home data on this host. |
| `/root/nixos-deploy-*`, `/root/archive` | ~508 MiB | deploy trees are recreatable; the archive copy is redundant (the durable copies are pius `/persist/archive/` and tiberius `/data/archive/`). |
| `/opt/containerd`, `/srv` | empty | unused. |

Anything else on `zlocal/root` (the Nix store is a separate dataset) would be regenerated by
the next boot or is a cache.

## To enable the rollback (not done yet)

1. Make sure the two migrated paths are current: docker writes to `/persist/var/lib/docker`
   directly, and `/root/.ssh` was copied; any `known_hosts` additions since then are minor.
2. Take the blank snapshot from the state you want every boot to return to:
   `zfs snapshot zlocal/root@blank` (the module defaults to `<rootDataset>@blank`).
3. In `flake.nix`'s `pius` block, set
   `{ cjv.impermanence.zfsBootRollback.rootDataset = "zlocal/root"; }` (hadrianus uses
   `zroot/local/root`; pius's pool is `zlocal`, so this is the corresponding value).
4. Rebuild + reboot. Verify the binds (`mount | grep zsafe/persist`), that docker starts on
   `/persist/var/lib/docker` (`docker info | grep "Docker Root Dir"`), the calibre-web
   container is healthy, and services such as postgresql, jellyfin, nextcloud, etc. come up.
5. After the first rolled-back boot, check `/root/.ssh` is the persisted copy and the
   archive is not expected there (it is on `/persist`).

Rollback of this change: unset `rootDataset` and rebuild; the root dataset is untouched
until the first rollback boot.
